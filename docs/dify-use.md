# Dify 接入原生 MCP 及 Agent 最佳实践指南

本指南总结了在 Dify 中高效接入和使用 Odoo MCP（或其他 MCP 服务）的标准流程。遵循此指南可避免常见的“大模型幻觉”、“调用慢”、“反复试错”等问题。

## 核心原则：拒绝第三方发现插件
**绝对不要使用** Dify 社区插件中的 `mcp_sse`（发现和调用 MCP 工具）节点。
*   **为什么不用？** 使用该插件会导致 AI 在每次提问时都要先调用底层 API 探查有哪些工具可用，浪费 Token、增加延迟（动辄思考 10+ 秒），且极易因为参数 JSON 格式错误而卡死在第一步。
*   **怎么做？** 使用 Dify 原生的 MCP 配置功能，让工具在应用启动时就直接“硬挂载”到 Agent 身上。

---

## 步骤一：在 Dify 平台配置原生 MCP 服务

1. 登录 Dify 控制台，点击顶部导航栏的 **“工具 (Tools)”**。
2. 在左侧菜单栏找到并点击 **“MCP”**。
3. 点击右上角的 **“添加 MCP 服务器 (Add MCP Server)”**。
4. 填写以下连接信息：
   * **名称**: `Odoo-MCP` (可自定义)
   * **传输方式**: `SSE`
   * **URL**: `http://<你的服务器IP>:8000/sse` 
     *(如果 Dify 和 MCP 服务部署在同一台机器的 Docker 环境下，请填 `http://host.docker.internal:8000/sse`)*
5. 点击保存。保存成功后，你能在界面上直接看到 MCP 服务暴露出来的所有具体工具（如 `search_records`, `get_record` 等）。

---

## 步骤二：在 Chatflow (工作流) 中使用 Agent 节点

如果你在编排复杂的 Chatflow 工作流，想要使用 MCP 工具，请严格按照以下步骤配置 Agent 节点：

### 1. 添加与配置 Agent 节点
1. 在画布中添加一个 **“代理 (Agent)”** 节点。
2. 在节点右侧的 **“工具 (Tools)”** 面板中点击添加，从列表中勾选原生 MCP 提供的具体业务工具（不要勾选任何与 list_tools 相关的工具）。

### 2. 注入防御性提示词 (Prompt)
将本仓库根目录下的 `prompt.md` 的完整内容，粘贴到 Agent 节点的 **“指令 (Instructions)”** 框中。
这套提示词能有效防止大模型：
*   猜测不存在的 Odoo 字段
*   将 Domain 传错为字典格式
*   输出冗长的 `<think>` 思考过程

### 3. 性能调优设置（解决出结果慢的问题）
在 Agent 节点的配置面板顶部，进行以下关键设置：
*   **推理模式 (Reasoning Mode)**: **必须从 `ReAct` 切换为 `Function Call / Tool Call`**（这能跳过大模型的自我独白，直接触发工具调用，响应速度可提升数倍）。
*   **最大迭代轮数 (Max Iterations)**: 设置为 `2` 或 `3`。
*   **输入变量精简**: 只关联最核心的变量（如 `sys.query`），不要把无关的超长文本作为对话上下文传入。

---

## 步骤三：格式化输出与展示

为了确保最终输出给用户（或传递给工作流下一个节点）的数据既美观又易于解析，请确保你的 Prompt 中包含了严格的排版指令。

Agent 节点会严格按照以下格式吐出纯净数据，不再附带任何寒暄废话：

```text
【数据解读】
姓名: 张三
工作邮箱: zhangsan@example.com
手机号: +86 138 0000 0000

【原始数据】
```json
{
  "name": "张三",
  "work_email": "zhangsan@example.com",
  "mobile_phone": "+86 138 0000 0000"
}
```
*(注意：外层包含 json 代码块标记，markdown 渲染时需处理转义)*
```

## 总结
通过 **原生 MCP 配置 + Function Call 模式 + 防御性系统提示词** 的组合拳，你的 Dify 智能体将能够以极低的延迟、100% 的传参准确率，完美地与 Odoo ERP 系统进行交互。
